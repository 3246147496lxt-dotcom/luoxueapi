# 落雪积分查看器产品需求（P0）

状态：会员周/月积分模式已确认

适用范围：独立 macOS / Windows 只读查看器，不接入现有 `desktop/`

## 1. 产品定义

落雪积分查看器是一款面向会员的额度状态工具，不是账户后台、账单页或缩小版
数据看板。

用户查看桌面悬浮窗时，应在 5 秒内回答：

1. 当前订阅的会员套餐是什么；
2. 本周积分还剩多少；
3. 本月积分还剩多少；
4. 当前是否可用；
5. 距离周积分重置还有多久，会员何时到期。

本地应用只承担快速查看。购买或管理会员、账户管理、充值、详细用量和排障统一
前往网站处理。

## 2. 已确认的业务口径

### 2.1 账户与会员范围

- P0 一次只连接一个账户；
- P0 按常见使用方式默认一个账户只有一个当前会员；
- 不设计多会员列表、切换、汇总或叠加额度；
- 没有当前会员时显示“暂无会员订阅”；
- P0 不根据 API Key、API Key 分组、设备或客户端拆分会员额度；
- 当前额度状态不代表模型、路由、RPM、并发或上游服务一定可用。

### 2.2 会员周额度与月额度

- 周额度采用连续 `7 × 24` 小时周期，不存在日额度或自然周额度；
- 月额度采用连续 `30 × 24` 小时周期；
- 周/月周期共同以会员开通的准确时间为不可变锚点，不是首次调用时间、自然周、
  自然月起点或本地零点；
- 套餐设置了 `monthly_limit_usd` 时使用该值；仅在该字段未设置（`NULL`）时，
  月额度上限取 `weekly_limit_usd × 4`；显式 `0` 表示月额度已耗尽；
- 未中断续费沿用原周期锚点；
- 会员过期后重新开通，或新套餐生效时，以新的生效时间建立周期锚点；
- 服务端分别返回周/月窗口权威的 `period_start`、`period_end` 和 `resets_at`；
- 客户端以 `resets_at` 为唯一重置时间来源，只负责显示动态倒计时和准确时间；
- 服务端百分比表示已用比例时，客户端将其换算为剩余比例；
- 剩余百分比面向用户显示为整数，圆环进度可保留精确比例；
- 百分比未知、会员失效或数据不可确认时显示 `—`，不得显示虚假的 `0%`；
- 会员到期、周额度重置和月额度重置是不同事件；悬浮卡“到期”只使用
  `subscriptions[].expires_at`，不得把任一窗口的 `resets_at` 写成到期时间。

### 2.3 桌面悬浮窗不展示的额度和用量

桌面悬浮窗不展示以下信息：

- 账户余额；
- 今日消费和本月消费；
- 已用、剩余或限额积分数值；
- Token 数量、请求数和任何用量趋势；
- API Key、API Key 分组或计费来源；
- Codex 或其他上游平台/账号池额度；
- 由余额、积分或历史用量反推的预计 Token、请求数或可用时长；
- 本地用量详情、图表或请求明细。

这些信息不会参与桌面悬浮状态卡的判断和展示。具体管理与完整用量仍以前往网站
查看为准。

菜单栏弹窗属于兼容保留的账户速览入口，不套用本节的展示限制。它继续显示
账户余额、今日/月消费和会员圆环，并允许点击会员卡向右展开既有的本周期
Token/请求详情。菜单栏与桌面悬浮窗必须使用独立组件，后续修改不得互相污染。

## 3. P0 信息架构

### 3.1 桌面悬浮窗

桌面悬浮窗有两种形态：

- 缩小态：原生窗口 `80×80`，可见卡片 `72×72`，只显示整数剩余百分比；
- 展开态：原生窗口 `314×314`，可见卡片 `306×306`，展示完整会员状态卡。

展开态按以下优先级排版：

1. 左上角：`CODEX · 套餐名`；
2. 套餐名下方：“周剩余”；
3. 中部：大字号整数剩余百分比；
4. 中部百分比外围：对应的剩余额度圆环；
5. 圆环下方：只显示动态倒计时，例如 `5 天 0 小时后重置`；
6. 右上角：单一状态点；
7. 底部显示权威月剩余百分比，会员到期日只显示月/日，例如
   `月剩余 74% · 8/25 到期`；必要时追加“旧数据”。

可用状态不重复显示“可用”徽章、图标或按钮，右上角绿色状态点已经足够。
单击缩小态展开，单击展开卡或按 `Esc` 收起。窗口无系统标题栏、无 macOS
三色圆点、透明留边、不可缩放并保持置顶；整个可见卡片使用统一半透明材质，
而不是只让局部装饰透明；顶部保留可拖动区域。

### 3.2 菜单栏

- 点击菜单栏入口后展示既有 `406×500` 账户速览；
- 保留账户余额、今日消费、本月消费和圆环会员卡；
- 会员卡仍以整数显示剩余百分比，圆环保留精确比例；
- 点击会员卡时，窗口向右扩展为 `822×500` 并显示既有本周期详情；
- 保留“打开完整面板”，调用后将桌面悬浮窗直接打开为 `314×314` 展开态；
- 菜单栏与桌面悬浮窗的数据来自同一快照，但 DOM、组件和窗口尺寸独立。

### 3.3 无会员

没有当前会员时：

- 明确显示“暂无会员订阅”；
- 百分比显示 `—`，不显示 `0%`；
- 不显示虚构的进度、周期或重置时间；
- 如提供操作，只能引导用户前往网站查看或开通会员。

## 4. 状态体系

| 状态 | 判断口径 | 状态点/进度 | 首屏说明 |
|---|---|---|---|
| 可用 | 会员有效且剩余大于 10% | 绿色状态点、蓝色进度 | 显示剩余整数百分比与重置时间 |
| 警告 | 会员有效且剩余大于 0%、不高于 10% | 黄色状态点和进度 | 本周额度即将用完 |
| 耗尽 | 会员有效且剩余为 0% | 红色状态点和进度 | 等待下个周期重置 |
| 失效 | 会员已过期、暂停或不可使用 | 灰色状态点和进度 | 会员已失效，前往网站确认 |
| 未知 | 服务端无法确认会员或额度 | 灰色状态点和空进度 | 暂时无法确认额度 |
| 旧数据 | 刷新失败但存在安全缓存 | 灰色状态点；保留上次进度 | 明确标注“上次数据”和最后成功更新时间 |

授权失效、无数据和旧数据属于数据可信度状态，优先于会员额度状态。旧数据可以
展示缓存中的套餐、百分比和 `resets_at`，但不得继续宣称当前“可用”；所有数值
必须明确属于上次成功同步。

## 5. 关键流程

### 5.1 首次连接

安装应用 → 使用系统浏览器确认只读授权 → 回到应用 → 拉取当前会员与周额度 →
展示会员状态卡。

### 5.2 日常查看

点击菜单栏入口或桌面悬浮窗 → 先展示安全缓存 → 后台刷新 →
确认套餐、周剩余、状态和距离重置的剩余时间。

### 5.3 前往网站

需要查看具体消费、Token、请求、账单，或购买/管理会员时，用户从查看器前往
网站处理；本地应用不复制这些功能。

### 5.4 离线或服务故障

存在缓存时保留上次成功数据并标记“上次数据”和最后同步时间；不存在缓存时
显示未知/暂时不可用。两种情况都不得用 `0%` 代替未知数据。

## 6. 认证、安全与缓存

- 应用只申请独立的 `quota:read` 设备授权；
- 授权在系统浏览器完成，应用不接收网站密码、验证码或 API Key；
- 应用内不得要求用户粘贴具有消费能力的 API Key；
- Refresh Token、安装标识和缓存密钥存放在应用数据目录的
  `credentials-v1.json`；
- Windows 使用当前登录用户的 DPAPI 加密整份凭据；macOS 使用 `0700` 应用
  数据目录和 `0600` 凭据文件权限；同一登录账户下运行的其他程序仍属于本地
  信任边界；
- Refresh Token 使用可恢复的 `candidate-v1` 轮换，避免网络回包丢失或应用
  重启时因盲目重试触发误判重放；
- 额度快照使用 AES-256-GCM 加密落盘，并按账户授权与展示时区隔离；
- 打开界面时可先显示安全缓存，再进行后台刷新；
- 退出连接必须清除本地令牌和额度缓存；
- 生产运行时不得加载演示数据。

## 7. P0 非目标

- 多账户同时登录；
- 多会员列表、切换、聚合或额度叠加；
- 应用内充值、购买/续费会员或修改账户；
- API Key 创建、编辑、分组切换或可用性判断；
- 账户余额、账单、消费或积分明细；
- Token、请求数、模型消费分析、趋势图和单请求分析；
- 预计可用 Token、请求数或使用时长；
- Codex、OpenAI、Anthropic 等上游账号池额度；
- 在桌面悬浮窗中展示本地详情页或右侧展开面板；
- CSV 导入导出和完整日志。

## 8. 数据与实现约束

- 客户端读取服务端返回的当前会员，不在本地合并多个会员；
- 客户端不得根据本地日期计算自然周；
- `resets_at` 是倒计时的唯一权威来源；
- 动态倒计时应随当前时间更新，悬浮窗不展示具体重置日期与时刻；
- 会员到期时间继续保留原始精度，但悬浮窗只格式化为月/日；
- 所有时间按用户展示时区格式化，但不得改变服务端代表的绝对时刻；
- 剩余百分比必须限制在 `0%–100%`，显示时取整数；
- 未知、无限、禁用、不适用和失效不得归一为 `0%`；
- 缓存快照必须包含最后成功更新时间和数据过期状态；
- 前端状态切换器和演示数据只用于开发预览，不得进入生产数据流。

## 9. P0 验收标准

- 桌面悬浮窗只回答套餐、周剩余、月剩余、状态、周重置时间和会员到期时间；
- 菜单栏保留账户速览和既有详情，不得把这些内容带回桌面悬浮窗；
- 两个入口的会员卡使用相同套餐与相同整数剩余百分比；
- 左上角显示 `CODEX · 套餐名`，其下显示“周剩余”；
- 剩余百分比为大字号整数，不出现小数；
- 右上角状态表达只使用一个状态点；
- 可用、警告、耗尽、失效、未知和旧数据均有独立、可辨识且不误导的表现；
- 无会员时显示“暂无会员订阅”，不得显示 `0%` 或虚构重置时间；
- 倒计时由当前时间动态计算，并与服务端 `resets_at` 的准确时间同时展示；
- 7 天周期按会员开通准确时间锚定，不按自然周或本地零点计算；
- 30 天周期按会员开通准确时间锚定；显式月额度优先，否则由服务端使用周额度
  乘以 4，客户端不得自行推导；
- “月剩余”后显示 `subscriptions[].expires_at`，不得误用月窗口重置时间；
- 桌面悬浮窗不展示账户余额、今日/月消费、积分已用/剩余、Token、请求数、
  API Key 分组或本地详情图表；
- 首次请求失败不得显示 `0%`；
- 旧数据必须显示“上次数据”和最后成功更新时间，不得继续宣称当前可用；
- 退出连接后本地令牌和缓存均被清除；
- 五名不了解实现细节的会员用户均能在 5 秒内回答：订阅什么套餐、本周和本月
  各还剩多少、是否可用、何时准确重置以及会员何时到期。
